> **Author:** Sahayak Engineering Team

## 1. Executive Summary

Sahayak is a production-grade, modular voice-assistant platform engineered as Alexa+ MCP add-ons. Operating over stateless Streamable HTTP (JSON-RPC 2.0), Sahayak provides conversational assistance spanning education, productivity, personal finance, health tracking, career development, household logistics, small business management, language acquisition, and civic information.

All 33 public tools comply strictly with Alexa+ voice UX constraints:
- Spoken summaries are strictly $\le 300$ characters.
- Spoken outputs contain zero markdown, emoji, raw symbols, URLs, or unreadable characters.
- Responses return structured envelopes with stateless state handles (`quiz_id`, `card_id`, `plan_id`).
- All financial numbers use integer minor units with ISO currency codes (zero floats).
- All timestamps are UTC in persistence and converted to user timezones only at spoken boundaries.
- Every mutating tool supports idempotency via `request_id`.

## 2. Multi-Add-On Deployment Architecture (ADR 0016)

To respect Alexa+'s tool budget and optimize NLU routing accuracy, Sahayak defines four targeted add-on bundles plus a full monolith profile:

| Profile | Add-On Name | Tool Budget | Actual Tools | Included Modules | Manifest Path |
|---|---|---|---|---|---|
| `study` | **Sahayak Study Companion** | 6 | 6 | Academics | `alexa/study/addon.json` |
| `life` | **Sahayak Daily Life** | 12 | 12 | Productivity, Finance, Health | `alexa/life/addon.json` |
| `work` | **Sahayak Work & Business** | 8 | 6 | Career, Business | `alexa/work/addon.json` |
| `home` | **Sahayak Home & Civic** | 10 | 8 | Home, Language, Local Info | `alexa/home/addon.json` |
| `full` | **Sahayak Platform (Monolith)**| 35 | 33 | All 10 Modules + Settings | `infra/` (Internal/Dev) |

All profiles execute from the same hardened container image and share a unified PostgreSQL and Redis persistence tier. User identities and cross-module context are fully preserved.

## 3. Public MCP Tool Catalog (33 Tools)

### Academics (6 Tools)
1. `quiz_start`: Initiates a multiple-choice topic quiz with Wikipedia-grounded questions.
2. `quiz_answer`: Processes spoken user answers with phonetic and case-insensitive matching.
3. `flashcards`: Manages flashcard decks with SuperMemo-2 spaced repetition reviews.
4. `study_plan`: Builds and inspects milestone-based exam preparation schedules.
5. `progress_report`: Summarizes mastery across topics and learning streaks.
6. `topic_brief`: Delivers grounded 2-3 minute audio briefs on academic topics.

### Productivity (6 Tools)
7. `tasks`: Manages prioritized tasks and due-date agendas.
8. `habits`: Tracks recurring daily/weekly habits with streak protections.
9. `notes`: Voice capture and search for personal memos.
10. `focus_timer`: Starts and checks Pomodoro focus intervals.
11. `daily_briefing`: Morning overview combining agenda, habits, and urgent alerts.
12. `weekly_review`: Adaptive cross-module weekly retrospective.

### Personal Finance (4 Tools)
13. `expense_log`: Logs categorized expenses in integer minor units.
14. `budget`: Sets monthly category limits and reports remaining allocations.
15. `split_bill`: Computes fair group bill splits with largest-remainder rounding.
16. `finance_report`: Generates monthly cash flow and spending breakdowns.

### Health & Wellness (2 Tools)
17. `health_log`: Records daily water intake, sleep hours, and step counts.
18. `health_summary`: Reviews hydration goals and weekly wellness trends.

### Career Development (3 Tools)
19. `interview_practice`: Interactive behavioral/technical interview drill simulator.
20. `application_tracker`: Tracks job pipeline statuses, interviews, and deadlines.
21. `career_practice`: Integrated career coaching and interview preparation.

### Home & Family (3 Tools)
22. `shared_list`: Manages collaborative household and grocery checklists.
23. `chores`: Coordinates recurring household chore assignments.
24. `pantry_recipes`: Suggests recipes utilizing on-hand pantry ingredients.

### Small Business (3 Tools)
25. `orders`: Manages customer orders and shipment tracking state machine.
26. `ledger`: Double-entry style customer balance ledger with audit trail.
27. `sales_summary`: Aggregates revenue analytics and monitors low inventory.

### Language Learning (2 Tools)
28. `vocab`: Word-of-the-day acquisition and SM-2 vocabulary review.
29. `language_practice`: Multi-turn conversational practice and grammar feedback.

### Local & Civic Information (3 Tools)
30. `transit_status`: Real-time public transit line status and advisory checks.
31. `commodity_prices`: Mandi agricultural commodity prices and modal rates.
32. `scheme_finder`: Eligibility rules engine for national welfare schemes.

### Settings & Controls (1 Tool)
33. `settings`: User preferences to inspect, enable, or disable assistant modules.

## 5. Post-Launch 7-Day Monitoring Checklist

### Day 1: Rollout & Smoke Verification
- [ ] Deploy ECS tasks with `DEPLOYMENT_PROFILE=full` (or individual profile tasks).
- [ ] Confirm `/healthz` returns `200 OK` and `/readyz` confirms DB and Redis connectivity.
- [ ] Run MCP Inspector smoke test against `/mcp` Streamable HTTP endpoint.
- [ ] Verify Cloudflare/ALB TLS certificate validity and HSTS headers.
- [ ] Verify CloudWatch/Prometheus metrics ingestion for `mcp_tool_calls_total`.

### Day 2: Authentication & Account Linking
- [ ] Monitor OAuth token exchange success rate at `/.well-known/oauth-protected-resource`.
- [ ] Verify JWKS cache hit ratio $> 99%$.
- [ ] Check logs for `auth_required` vs `forbidden` error rates.
- [ ] Verify zero PII or unhashed tokens in CloudWatch Structured Logs.

### Day 3: Voice Latency & Provider Budgets
- [ ] Verify p95 non-generating tool latency $\le 800\text{ ms}$.
- [ ] Verify p95 `quiz_start` cache-hit latency $\le 1.0\text{ s}$.
- [ ] Verify p95 `quiz_start` generation latency $\le 5.0\text{ s}$.
- [ ] Inspect Gemini / Groq fallback circuit breaker rates ($< 1\%$).
- [ ] Verify daily LLM budget guard adheres to configured limits.

### Day 4: Data Integrity & Outbox Worker
- [ ] Check `core.outbox_events` backlog size (should remain near 0).
- [ ] Confirm dead-letter table `core.dead_letter_events` is empty.
- [ ] Test admin CLI `scripts/admin.py replay-dead-letter` on staging environment.
- [ ] Confirm background prefetch worker generates quiz questions for cached topics.

### Day 5: User Preferences & Feature Flags
- [ ] Confirm `settings` tool handles module enable/disable commands reliably.
- [ ] Test percentage rollout hash distribution on test cohorts.
- [ ] Verify audit log entries in `core.audit_log` for all administrative actions.

### Day 6: Cross-Module Review & Weekly Aggregations
- [ ] Execute `weekly_review` across user accounts with varying module configurations.
- [ ] Verify speech formatting length remains $\le 300$ characters under dense data scenarios.
- [ ] Verify no database deadlocks during concurrent weekly summary queries.

### Day 7: Operational Review & Sign-Off
- [ ] Perform database point-in-time recovery (PITR) drill on staging replica.
- [ ] Review error budget consumption (Availability target: $\ge 99.9\%$).
- [ ] Finalize post-launch operational handoff to on-call team.
